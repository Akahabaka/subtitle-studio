# Release 发布流程

参考 [Subtitle Edit](https://github.com/SubtitleEdit/subtitleedit/releases)、[LosslessCut](https://github.com/mifi/lossless-cut/releases) 的版本说明与附件组织，遵循 [GitHub Release 文档](https://docs.github.com/en/repositories/releasing-projects-on-github/automatically-generated-release-notes)。

1. 固定完整提交 SHA，确认对应 Windows CI 成功，运行变更相关的真实媒体测试。
2. 发布自包含 Windows x64 目录，加入固定版本引擎、第三方许可证、使用说明及验收报告。源码归档必须来自同一个提交。
3. 检查运行库签名，压缩后检查 CRC、必要文件和应用 DLL；计算两个压缩包的 SHA-256。
4. 创建 Release 草稿，标明版本、对应提交、功能变化、下载方法、已验证与未验证项。候选版标为 prerelease，不能因上传成功就宣称全部验收完成。
5. 上传 Windows 完整包、源码包、SHA256.txt。大文件使用流式发送、进度输出和超时处理；网络中断不等于支持断点续传。
6. 重试前读取远端附件状态。已完成且大小、SHA-256 一致的附件跳过；本次草稿中失败的 starter 附件可清理后重新上传。不要覆盖已公开版本的附件。
7. 三个附件都验证通过后公开草稿，再通过无身份凭据的公开 API 确认下载链接、大小和摘要。

## GitHub CLI 对应命令

已安装并登录 GitHub CLI 的维护者可以使用下列命令。版本号、提交 SHA 和文件路径需替换为本次已验证值。

```powershell
gh release create vX.Y.Z-rc.N --repo Akahabaka/subtitle-studio --target FULL_COMMIT_SHA --draft --prerelease --title "字幕工坊 X.Y.Z RC N" --notes-file release-notes.md
gh release upload vX.Y.Z-rc.N SubtitleStudio-win-x64.zip SubtitleStudio-source.zip SHA256.txt --repo Akahabaka/subtitle-studio
# 核对远端附件大小和 SHA-256 后再公开：
gh release edit vX.Y.Z-rc.N --repo Akahabaka/subtitle-studio --draft=false
```

[gh release upload 官方文档](https://cli.github.com/manual/gh_release_upload)。不默认使用 `--clobber`，避免误覆盖已有附件。凭据只交给凭据管理器或 CI 密钥，不写入仓库、发布说明或技术日志。

当前 CI 负责构建和运行库检查；当前发布仍由维护者执行并核验，尚未实现完整自动发布流水线。未来迁移到 Actions 时，应先固定引擎下载来源和校验值，补齐真实媒体测试，再授予发布作业最小写权限。
